# 📄 Completion Schema — Example Payloads

This document contains representative JSON examples for the `Completion` entity. These examples reflect real-world completions generated by different models in ReasonOps and how they are structured in the system.

---

## ✅ Example 1: Claude Completion with Metadata

```json
{
  "id": "completion_001",
  "taskId": "task_001",
  "response": "Planting more trees in cities helps reduce heat, filter air, and improve mental health.",
  "model": "claude",
  "steps": [
    "Trees reduce the urban heat island effect.",
    "They filter pollutants from the air.",
    "They create calmer, more walkable spaces that improve mental health."
  ],
  "createdAt": "2025-05-12T08:30:00Z",
  "updatedAt": "2025-05-12T08:30:00Z",
  "metadata": {
    "tokenCount": 36,
    "temperature": 0.5,
    "llmVersion": "claude-v2.1"
  }
}
```

> A Claude completion using moderate temperature. Three reasoning steps have been parsed and will be evaluated separately.

> A single-paragraph GPT response with no pre-parsed steps. Steps may be extracted later via the step parsing service.

## ✅ Example 3: Ollama Response with Rich Metadata

```json
{
  "id": "completion_003",
  "taskId": "task_004",
  "response": "Deploying drones in conflict zones raises ethical concerns around accountability, civilian risk, and autonomy.",
  "model": "ollama",
  "steps": [
    "Accountability may be unclear when drones make mistakes.",
    "Civilian harm can be hard to predict or prevent.",
    "Autonomous decision-making in lethal contexts is highly controversial."
  ],
  "createdAt": "2025-04-01T09:05:00Z",
  "updatedAt": "2025-04-01T09:05:00Z",
  "metadata": {
    "deploymentEnv": "localhost",
    "modelRunId": "ollama-qa-0423",
    "systemPrompt": "Reply in ethical analysis tone."
  }
}
```

> Example from a local LLM (Ollama) showing optional metadata fields and integration with custom model configs.

---

## 🔁 Notes

- Completions should always be traceable to a valid `taskId`
- Field `steps` can be empty if parsing hasn’t occurred yet
- Metadata should only include serializable key-value pairs

See [`model.md`](./model.md) for field-level documentation.
