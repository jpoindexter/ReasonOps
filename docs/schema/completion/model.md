# 📄 Completion Model
The `Completion` entity represents the full text response generated by a language model (LLM) for a specific `Task`. It is a central output of the ReasonOps reasoning pipeline and serves as the source of evaluation, step parsing, and judgment.
---
## 🧠 Purpose
Each Completion contains:
- The raw LLM response generated from a specific Task
- The model used (e.g. Claude, GPT, Ollama)
- The sequence of parsed reasoning steps derived from the response
Completions are immutable once evaluated. New completions (e.g. from different models or after prompt changes) should be stored as additional entries.
---
## 🔡 TypeScript + Zod Schema
```ts
import { z } from "zod";
export const CompletionSchema = z.object({
  id: z.string(), // Unique identifier (UUID)
  taskId: z.string(), // Foreign key linking back to the Task
  response: z.string().min(1), // Full raw text generated by the LLM
  model: z.enum(["claude", "gpt", "ollama"]), // Model that generated the response
  steps: z.array(z.string()), // Optional: step IDs or inline steps may be added separately
  createdAt: z.string(), // ISO timestamp
  updatedAt: z.string(), // ISO timestamp
  metadata: z.record(z.unknown()).optional(), // Arbitrary extension field
});
export type Completion = z.infer<typeof CompletionSchema>;
```
---
## ✅ Required Fields
| Field       | Type     | Description                                |
| ----------- | -------- | ------------------------------------------ |
| `id`        | `string` | Unique identifier for this completion      |
| `taskId`    | `string` | References the source Task                 |
| `response`  | `string` | Raw output from the model                  |
| `model`     | `enum`   | Specifies which model generated the output |
| `createdAt` | `string` | Timestamp of creation                      |
| `updatedAt` | `string` | Last modification timestamp                |
---
## 🆗 Optional Fields
| Field      | Type                              | Description                                                            |
| ---------- | --------------------------------- | ---------------------------------------------------------------------- |
| `steps`    | `string[]` or `Step[]` (external) | IDs or inline reasoning steps derived from the response                |
| `metadata` | `Record<string, unknown>`         | Custom attributes (e.g., token count, temperature, system prompt used) |
---
## 🔗 Related Models
- `Task`: A Completion is always linked to one Task
- `Step`: Steps are derived from the Completion's response
- `Judgment`: Linked via Steps for scoring
See: [`/docs/schema/relationships.md`](../relationships.md)
---
## 🔁 Model Usage in App
| Location                 | Purpose                                                        |
| ------------------------ | -------------------------------------------------------------- |
| `/api/llm/route.ts`      | Accepts a `Task` and returns a new `Completion`                |
| `/app/evaluate/[taskId]` | Uses `Completion` content to parse and display Steps           |
| `/lib/llmAdapter.ts`     | Model switcher determines which API to use (Claude, GPT, etc.) |
---
## 🔐 Contributor Notes
- A new Completion should only be created after Task submission
- Once Judgments are applied to its Steps, the Completion should not be edited
- Ensure model name matches supported enums
- Always log `createdAt` and `updatedAt` at time of persistence
